# 테스트 계획

> 테스트 도구는 저장소/스택 설정 후 선택한다. 아래는 시나리오와 기대 결과 기준이며 실제 수행 결과가 아니다.
> Figma에는 가입/로그인 화면 없이 모의 펀딩 참여 및 비밀번호 코멘트 수정 UI가 있다. 실제 결제는 범위에 없다. TC-06~TC-12의 서버 검증은 API 계약과 DB 구현이 준비된 뒤 실행한다. 그 전에 UI 상태/입력 표시 테스트는 진행할 수 있다. P0/P1은 검증 우선순위 제안이다.
> 현재 GitHub `main`에서 확인되는 것은 Vite/React 화면 scaffold와 ESLint 설정이다. `pnpm lint`/`pnpm build` 명령은 저장소에 있지만 실행 결과를 이 문서에서 주장하지 않는다. 테스트 도구 미정 문구는 기능 자동화 테스트 도구를 가리킨다.

## 실행 시 기록할 항목

각 시나리오에 실행 환경, 테스트 데이터, 결과(Pass/Fail/미실행), 재현 절차, Issue 링크를 기록한다. P0 실패는 배포 차단으로 제안한다. 자동화 범위와 실제 통합/수동 테스트 비율은 팀 합의 후 정한다.
