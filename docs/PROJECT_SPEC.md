# CineFund 프로젝트 개발 명세

> 기준: 기존 기획안 최종 수정 2026-10-08 및 GitHub `main` 현재 상태 점검 · 저장소는 생성되었고 프런트엔드 scaffold가 있으나 기능 구현은 초기 단계다.

## 배경 및 가치

영화의 정보를 탐색하고 여러 작품의 정보를 비교한 다음, 실제 결제 없이 가상 금액을 배분해 보는 경험을 제공한다. 목표는 영화 선택을 돕고 펀딩 현황을 재미있게 확인하는 것이다.

## 사용자 시나리오

1. 사용자는 `/`에서 지정된 영화 목록을 랜덤 순서로 둘러보고 추가 목록을 불러온다.
2. 정렬 기준을 선택하거나 영화 상세로 이동해 DB에 저장된 TMDB 영화 정보와 펀딩 현황을 본다.
3. 비교 화면에서 2~5편을 선택하고 결과를 확인한다.
4. 로그인이나 실제 결제 없이 상세 화면에서 모의 펀딩 정보를 입력해 기록을 남긴다. 입력 검증·요청 형식 등 구체 서버 계약은 API 담당자와 합의한다.
5. 사용자는 코멘트 목록을 보고 비밀번호 확인 팝업으로 수정을 시도할 수 있다. 실제 수정 권한/요청 처리는 API 및 팀 합의 후 확정한다.

## 범위

### 포함

영화 100편 조회/상세, 무한 스크롤, 2~5편 비교, 비교 결과, 비로그인 모의 펀딩 및 코멘트 수정, 랭킹을 서비스 목표 범위로 한다. 로그인/회원가입과 실제 결제는 제외한다. 펀딩 등록·수정의 구체 API 계약과 목표액/집계 규칙은 API 담당자와 합의가 필요하다. 검색 UI와 AI 요약 팝업은 시안에 있으나 검색 범위와 AI 외부 서비스 연동은 미확정이다.

### 제외

로그인/회원가입, 실제 결제·환불, 쿠키 및 localStorage 기반 사용자 상태 관리, 100편을 넘는 영화 수집(초기 범위), 운영 수준의 금융/개인화 기능.

## 비기능 요구사항

- API와 DB 접근은 서버가 담당한다. 프런트엔드에 DB 자격 증명을 두지 않는다.
- 서버 등록 API를 구현할 때 입력 검증은 반드시 서버에서 수행하고 클라이언트 검증은 사용성 보조로 사용한다. 금액/필드별 상세 규칙은 합의 후 정한다.
- 코멘트 수정용 비밀번호를 쓰는 흐름이 확정되면 평문 저장/응답하지 않고 검증된 해시만 저장한다.
- 페이지네이션 결과는 중복과 누락을 줄이도록 안정적인 정렬 키를 사용한다.
- 오류 응답에는 내부 경로, SQL, 스택, 비밀 값을 노출하지 않는다.
- 모바일 레이아웃은 지원 목표이며 브레이크포인트/디자인은 Figma 결정 후 확정한다.

## 제약 및 외부 의존성

기획에서 React/JSX/HTML/CSS, Node.js, PostgreSQL, Prisma를 정했다. 현재 `main` FE 도구는 Vite, React Router, Tailwind CSS v4, React Compiler, ESLint, pnpm이다. React/JSX scaffold 외 기능은 초기 단계이며 BE/DB는 저장소에 아직 확인되지 않는다. Prisma는 백엔드 ORM이고 Express는 미정이다. TMDB는 지정 100편을 초기 seed/import할 때 호출해 메타데이터를 DB에 저장하며 앱 요청 때 실시간 호출하지 않는 구조를 계획한다. API 키와 초기 적재 실패/갱신 절차를 정해야 한다. 영화 목표액 산정 통화와 환율도 미정이다.

## 확장 계획

영화 검색 UI는 Figma에 포함되어 있으나 실제 검색 기능/API의 MVP 포함 여부는 TBD다. 영화 데이터 범위는 현 MVP에서 지정 100편을 우선하고, 추가 확장은 후속 범위로 둔다.

모의 펀딩은 서비스 목표이며 실제 결제는 없다. Figma 화면만으로 API/DB 계약이 확정되는 것은 아니므로 등록·집계·수정의 세부 구현은 API 담당자 및 팀 합의 후 명세한다. `DATABASE_SCHEMA.md`는 별도 검토·수정 대상으로 둔다.

## 완료 기준

- 필수 기능의 사용자 흐름과 예외 동작이 PRD/API/페이지 명세에 맞게 구현되고 팀 테스트 계획의 P0 시나리오를 통과한다.
- 모의 펀딩을 구현하는 경우 DB 제약과 금액 집계가 정합성을 유지하며, 수정 비밀번호를 사용하는 경우 평문이 저장/응답되지 않는다.
- 반응형 핵심 화면, 오류/빈/로딩 상태, README 실행 안내가 검토 가능하다.
- 배포 여부와 최종 검수 기준은 일정/팀 합의 후 확정한다.

## 기술 쟁점 분석

저장소 상태 확인: Vite/React JSX 프런트엔드 scaffold와 경로 placeholder가 `main`에 있다. 현재 확인한 트리에는 Node.js 백엔드, Prisma schema/migration, PostgreSQL 실행 설정, TMDB seed/import가 없다. 이는 프로젝트 목표에서 제외된 것이 아니라 아직 착수/등록되지 않은 상태다. 세부 패키지와 실행 명령은 [TECH_STACK](TECH_STACK.md), 화면 경로 비교는 [PAGE_SPEC](PAGE_SPEC.md)을 기준으로 한다.

| 항목 | 현재 상태 / 문제 및 영향 | 권장 해결책 | 합의 |
|---|---|---|---|
| Prisma 분류 | 기획상 DB처럼 읽힐 수 있으나 ORM임 | Node 서버의 ORM으로 표기 | 아니오, 바로잡음 |
| React-서버 통신 | 직접 연결 방식 미정 | HTTP API로 통신, 서버가 DB 접근 | API 스타일은 제안 |
| 영화 100편 적재 | 목록/식별자/초기화 방식 미정 | 외부 ID 포함 seed/import 스크립트와 검증 가능한 목록 준비 | 예 |
| 랜덤+무한 스크롤 | 매 요청 재랜덤하면 중복/누락 | 첫 요청에서 고정된 순서(시드/세션 또는 저장 순서)를 만들고 cursor 기반 유지; 사용자 상태 저장 제한과 조정 | 예 |
| TMDB 의존성 | 초기 100편 적재 시 키/쿼터/네트워크 장애 가능 | 고정 ID 목록을 기준으로 server-side seed/import에서 DB에 저장; 재실행·부분 실패 처리와 정책 확인 | 예 |
| 제작비=목표액 | 통화/환율/0 또는 미상 값 문제 | 목표액 별도 필드로 저장, 정책 정하기 전 원화 변환/동일시 금지 | 예 |
| 달성률 | 공식 미정, 목표 0 문제 | 제안: 누적액 / 목표액 × 100, 목표액 미정·0은 계산 불가 표시 | 예 |
| 동시 펀딩 | 읽기-더하기-쓰기는 lost update 가능 | 펀딩 기록을 원장으로 저장하고 DB 트랜잭션/집계 또는 원자적 갱신; 기록이 원본 | 예 |
| 모의 펀딩 | 결제 없이 실제 금전으로 오해 위험 | UI 전반에 모의/가상임을 표시, 결제 정보 수집 금지 | 예 |
| 코멘트 수정 | 로그인 없이 비밀번호만으로 권한 부여 | 강한 해시(예: Argon2id/bcrypt 검토), rate limit, 단일 코멘트 ID 및 검증 절차 | 예 |
| 길이 검증 | 문자 기준/공백/이모지 정의 미정 | 서버에서 trim 후 Unicode 기준 상한 검증; FE 동일 표시 | 예 |
| 비교 항목 | 비교 결과 필드 미정 | 공통 항목 후보를 확정하고 누락 정보 표시 정의 | 예 |
| 데이터 구분 | list/funding DB는 논리 구분 | 한 PostgreSQL 내 Movie와 Funding 테이블 관계 | 아니오, 제공 정보 기준 |
| 상태 저장 금지 | 비교 선택은 새로고침 시 사라질 수 있음 | URL query로 ID 전달하는 안 제안, 길이/새로고침 UX 검토 | 예 |
| FE/BE 배포 | 플랫폼 미정, CORS/환경변수 영향 | 독립 정적 FE와 Node API 배포 후보 비교, 동일 도메인/허용 origin 결정 | 예 |
| 보안/리소스 | 무제한 내부 요청, 초기 TMDB import 호출 실패/과다 요청 위험 | 내부 API 페이지 크기 상한, 서버 검증, 요청 제한 검토; import 재시도·호출 간격·키 보호 | 예 |
